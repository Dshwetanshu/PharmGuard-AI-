The Problem

A base LLM will sound right. That's the danger.

Ask ChatGPT whether lisinopril interacts with spironolactone. You'll get a fluent, partially-correct answer. You will not get a record ID you can verify. You will not get a guarantee that all 45 pairs in a 10-drug regimen were checked. You will not get an explicit flag when the model has no evidence for a pair — only a confident silence indistinguishable from a confident correct answer.

In medicine, a fluent guess is the worst possible output. It sounds authoritative to the reader and it's invisible to the writer. PharmGuard is built around the opposite premise: retrieval first, generation second, and citation mandatory at every step.

A system that scores 92% retrieval recall but has a 15% hallucination rate is not a success. This project defines what silent failure looks like before it defines what success looks like. — Project proposal, Phase 6
Architecture

Plan, retrieve, generate — in that order.

The pipeline deliberately separates deterministic work (pair enumeration, database lookups) from generative work (prose synthesis). The LLM is only invoked where fluent clinical language is the actual product — never to enumerate, look up, or classify severity.

What the system guarantees

Three invariants a base LLM cannot provide.

01 / Structured retrieval
Exact-pair lookups, not semantic guesses.
For "does A interact with B?", a database index beats vector similarity every time. PharmGuard hashes pairs and does O(1) lookups against 300K+ records. Vector search is reserved for unstructured context like patient reviews.
02 / Combinatorial completeness
All pairs enumerated, always.
A 10-drug list has 45 unique pairs. Every one is checked via itertools.combinations — no LLM enumeration, no chance of silent omission. The count is provably correct.
03 / Grounded generation
Every clinical claim cites its source.
The generator prompt enforces inline [SOURCE:RECORD_ID] citations. Pairs with no retrieved data are declared explicitly. A deterministic fallback produces a cited report even without an LLM.

Evaluation

Failure defined before success.

The six metrics below are committed targets, not claimed results. Ground truth for recall and precision is derived programmatically from the loaded interaction table — whatever dataset you ingest, the evaluator stays self-consistent.

Metric What it measures Target
Retrieval Recall Fraction of ground-truth interaction pairs surfaced by the retriever. ≥ 95%
Retrieval Precision Fraction of retrieved results that exist in ground truth. ≥ 90%
Faithfulness Does the generated mechanism match the retrieved source record? (LLM-judge + 20% human audit.) ≥ 85%
Hallucination Rate Clinical claims in the report that cannot be traced to any retrieval evidence. ≤ 5%
Severity Accuracy Severity tier in the report matches the severity field of the source record. ≥ 90%
Completeness Flagging No-data pairs explicitly declared in the report (contract check, not learned). 100%
Data Sources

Narrow by design. Authoritative by default.

PharmGuard does not learn from Reddit threads or unvetted scrapes. Its knowledge base is peer-reviewed or government-maintained, versioned, and cited. In medicine, the cost of breadth without rigor is measured in patient harm.

TWOSIDES
Primary · drug-drug interactions
Tatonetti Lab / Science Translational Medicine. ~4.6M signal-mined pair records with PRR statistics; severity tiers derived from PRR thresholds.
DrugBank 5.x
Drug metadata · synonyms · mechanisms
University of Alberta, peer-reviewed. ~14,000 drug entries. Powers the normalizer's synonym resolution layer.
SIDER
Side-effect context per drug
EMBL-curated side-effect resource mined from FDA drug labels. Used to supply per-drug adverse-event context alongside pair interactions.
RxNorm
Normalization backbone
US National Library of Medicine. Brand ↔ generic ↔ RXCUI mapping. Free with UMLS license.
WebMD Reviews
Patient-experience context (stretch)
Kaggle/public. Used only as unstructured vector-search context — never as evidence for interaction claims.
Medicare Part D
Prescribing-pattern analytics (stretch)
data.gov. Useful for population statistics but deliberately excluded from the interaction-detection core — prescribing patterns ≠ interactions.
Ethical Commitments

The system knows what it doesn't know.

No patient data is stored.

Medication lists are processed in memory only. No persistence, no logging of inputs, no identification of users. The web interface is stateless by design.

Coverage is declared, not implied.

Every output includes a Coverage Note stating which databases were queried and what their known limitations are. TWOSIDES skews toward English-language labels and US-marketed drugs; this is surfaced, not hidden.

Absence of data is a first-class output.

When the retriever returns nothing for a pair, the system states "No interaction data available" — explicitly, in the final report. A confident silence is the failure mode this project is designed to prevent.

It is not a doctor, and says so.

Every output carries a disclaimer that PharmGuard is decision support, not medical judgment. The disclaimer is a safety invariant — it is appended by the pipeline, not by the model.

Medical Disclaimer PharmGuard AI is a decision-support tool grounded in public pharmaceutical databases. It is not a substitute for professional medical judgment. Always consult a licensed clinician or pharmacist before making changes to a medication regimen.
